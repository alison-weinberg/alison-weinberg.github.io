The Challenge

Build a scenario-based module where learner choice has real consequence, without forcing linear paths or locking content behind arbitrary gates. The system needed to support differentiated reading levels for a single learner population, deliver content asynchronously based on learner actions, and assess reasoning rather than completion.

Architecture

The module runs on a 75+ variable system in Articulate Storyline that drives map gating, NPC dialogue states, content delivery timing, and branching progression. A custom JavaScript/localStorage bridge powers a persistent inbox, solving a known Storyline limitation where the GetPlayer() API doesn't function inside iframes.

This required understanding both Storyline's execution model and browser storage behavior, and resulted in a fully custom interface (read/unread states, persistent state across sessions, image attachment overlays) embedded as a web object.

"The choice not to read something has consequences down the line."

Key Design Decisions

Choice architecture with consequence

Learners aren't forced to review every available resource. Instead, a scored assessment dialogue evaluates whether learners engaged with relevant content, mirroring real workplace decision-making, where the choice not to read something has consequences down the line.

Dual reading levels as differentiation, not duplication

A single controlled variable toggles between two language registers across all NPC and narrative content, while interface elements remain consistent across both modes, so the navigation experience doesn't change, only the voice of the story does. One build serves multiple instructional contexts without maintaining parallel versions.

Delayed delivery as spaced practice

Content submitted by the learner doesn't return immediately, it arrives after the learner has moved to other tasks, using idempotent triggers that resolve correctly regardless of how many times a learner revisits the trigger point. This creates natural spaced retrieval: initial engagement, intervening activity, then integration of returned results.

Standards Alignment

While the forensic framing is the hook, the mechanics map directly to Common Core ELA standards for grades 9-12:

  • RL.9-10.1Evidence-based inference: the lab pipeline requires citing specific evidence to support conclusions
  • RL.9-10.3Character analysis: witness interviews reveal motive and development through dialogue
  • W.9-10.1Argument writing: the debrief requires a defensible claim built on gathered evidence

Reflection

Most of my day-to-day work runs on templated builds, optimized for rapid delivery and fast QA turnaround. This project was a deliberate departure from that, and it taught me things the templates don't.

The variable architecture wasn't complexity for its own sake. A single numeric routing variable, idempotent delivery triggers, and consistent state management were a QA strategy: the build is more predictable to test, not less, because every state is accounted for rather than handled ad hoc at each decision point. That's a lesson I now bring back to scoping conversations on templated work, where branching often gets avoided because it's assumed to be unpredictable.

I also went deeper into JavaScript and web object integration than I had before, and explored how AI-assisted workflows can support build complexity and QA efficiency on projects like this, an area I'm continuing to develop.

Beyond the Portfolio

The module is designed as a potential commercial product for secondary English and theatre educators, with a built-in path to licensing information for interested reviewers.

The forensic framing also creates a natural bridge for ELA and science co-teaching, evidence analysis and reasoning about lab results echo the kind of scientific thinking a partnering science class could build on. The current module doesn't teach lab science content, but the structure is there for a future cross-curricular collaboration.

Built to prove a system, not just tell a story.
